# 確率的シミュレータでのエージェント評価プロトコル

対戦AIの版比較で**偽陽性を掴まないため**の測定規律。ポケカABC（Kaggle PTCG AI Battle Challenge）で実際に起きた偽陽性事件（後述）から抽出した。エンジン固有の詳細（ポケカABC）は末尾の付録に分離。

## 鉄則（すべての比較で守る）

1. **同時対照・同一N・同一セッション**：比較する全アームは同じスクリプト実行内で、同じ相手・同じNで回す。別セッション・別Nの数字同士を突き合わせない（これが偽陽性の主因だった）。
2. **事前登録**：走らせる前に「主要比較は◯ vs ◯、N=◯、判定基準は差CIが0を含まないこと」を宣言。結果を見てから比較を選ばない。それ以外の数字は全て「探索的」とラベルする。
3. **昇格には複製必須**：有意に見えた結果は、**新規プロセスで同条件複製**に通ってから初めて採用・報告する。1回の有意は暫定。
4. **N最低500/アーム**。N=500の検出可能差は約±6pt。5pt差の検出（80%検出力）は約1,600戦/アーム、3pt差は約4,400戦/アーム。試合が速い（≈0.1秒/試合）ならNをケチる理由はない。
5. **先攻/後攻は毎試合交互**にしてバランスさせる（先攻有利が大きい環境がある。実測でミラー先攻固定62%の例）。
6. **勝率はWilson信頼区間、アーム間比較は2標本差CI**で判定。「有意差なし」は「等価」ではない——「±◯pt以上の差は無い」としか言えない。
7. **ラダー/リーダーボードのスコアを版比較の判定器に使わない**。収束前レーティング＋相手非固定で解像度が足りない（実例：ラダー順位とローカル実測が逆転）。

## 落とし穴カタログ（実際に踏んだもの）

- **勝者の呪い**：異常に悪く見えた測定値をきっかけに実験を組み、その異常値自体をベースラインに使うと、平均回帰の分だけ「効果」が必ず出る。対策＝比較対象は必ず同時に測り直す。
- **CI非重複の過信**：検定基準が保守的でも、**どの数字を比較するかの選択**に入ったバイアスは防げない。
- **発火率を測らずヒューリスティックを評価**：条件分岐が3%の試合でしか発火しないなら、勝率を動かす力はそもそも無い（dead code）。改修の評価前に必ず発火率を計測する（カウンタ1行）。
- **事後条件付けの誤読**：「発火した試合の勝率100%」は発火条件（有利な盤面）への選択効果であり、因果ではない。
- **直接対戦の検出力不足**：骨格がほぼ同一の2版の直接対戦は、差が出る試合自体が少なく検出力が低い。**第三者の固定相手**に両者をぶつける比較のほうが感度が高い。
- **同一基準の不徹底**：撤回した主張と同じ証拠水準（単一セッション・未複製）の他の主張を生かしたままにしない。
- **完全一致への無警戒**：2アームの成績が完全一致したら約2.5%の偶然か配線バグ。モジュールのフィンガープリント（識別printや挙動プローブ）で本当に別コードが動いたか確認。

## 標準手順

1. ハーネスの健全性確認：ミラー（同一エージェント同士）N≥300で勝率が50%をCI内に含むこと。エンジンが決定論的か（同一対戦2回で一致するか）も確認。
2. 較正（推奨）：陰性対照＝同一版同士をN=500×数回回し偽検出率≈5%を確認。陽性対照＝意図的に弱体化した版で既知の差を検出できるか。
3. 主要比較を事前登録して同時実行（鉄則1-2）。
4. 有意なら新規プロセスで複製（鉄則3）。通ったら採用。
5. 改修の評価では発火率カウンタを必ず同梱。
6. アブレーションは「束」と「個別」を区別：束OFFで因果が言えるのは束の合計効果まで。個別寄与は個別アブレーションで。

## 統計ユーティリティ

Wilson CI・2標本差CI・マッチアップ実行の実装は `references/cabt_harness.py` にある（ポケカABC用だがエンジンアダプタ以外は汎用）。数式だけ要る場合：Wilson CI は `(p + z²/2n ± z√(p(1-p)/n + z²/4n²)) / (1 + z²/n)`、2標本差CIは `d ± z√(p₁q₁/n₁ + p₂q₂/n₂)`。

## 付録：ポケカABC（Kaggle PTCG AI Battle Challenge）固有事項

- エンジンは `sample_submission.zip`（Dataタブ配布）内の `cg/` パッケージ。`libcg.so`(Linux)/`cg.dll`(Win)。**確率的でシード外部固定不可**＝共通乱数ペア比較は使えない。N増で対応。
- ドライバAPI：`cg.game.battle_start(deck0, deck1)`（**deck0が先攻**）→ `battle_select(list[int])` → `battle_finish()`。
- obs_dict：`current.result` が -1:対戦中/0:P0勝ち/1:P1勝ち/2:引分。`current.yourIndex` が手番。`select.option` のindexのlistを返す（デッキ選択局面のみ60枚のカードID）。
- 速度 ≈0.09秒/試合。エージェントは対戦中LLM呼び出し不可（オフライン隔離）。例外・タイムアウトは敗北＝合法手フォールバック必須。
- 実測済みの環境知見：ルカリオミラーで先攻有利≈+12pt（v4ポリシー・単一セッション、**要複製**）。v2/v3/v4はミラー実質パリティ（N=500基準）。瀕死保護ヒューリスティックは発火率3%の不活性コード。
