# 測定プロトコル要約

詳細は `skills/stochastic-agent-eval/SKILL.md` を参照。本ファイルはポケカABC固有の適用ルールのみ記載。

## 鉄則（全比較で守る）

1. **同時対照・同一N・同一セッション**：比較する全アームは同じスクリプト実行内で、同じ相手・同じNで回す。別セッション・別Nの数字を突き合わせない（偽陽性の主因）
2. **事前登録**：「主比較はAvsB、N=◯、判定基準はCI下限>◯%」を走らせる前に宣言。結果を見てから比較を選ばない
3. **昇格には複製必須**：有意に見えた結果は新規プロセスで同条件複製してから採用
4. **N最低400/アーム（推奨500以上）**：N=400の検出可能差 ≈ ±7pt。5pt差の検出（80%検出力）は約1,600戦/アーム
5. **先攻/後攻は毎試合交互**にしてバランス（先攻有利+14ptがある）
6. **Wilson CI + 2標本差CI** で判定。「有意差なし ≠ 等価」

## ポケカABC固有の設定

- エンジン：確率的・シード外部固定不可 → N増で対応（共通乱数ペア比較は使えない）
- 速度：1試合 ≈ 0.09秒。N=1,000 ≈ 90秒
- obs_dict：`current.result` が -1=対戦中/0=P0勝ち/1=P1勝ち/2=引分。`current.yourIndex` が手番
- ラダーEloは判定器として使わない（収束前ノイズ + 相手非固定）

## ガントレット測定の基準

- N=400/マッチアップ（最低限）。結論を出すなら N=1,000 推奨
- 相手は性格が異なる2体以上（Goodhart対策：自作相手1体への過適合防止）
- 現在の相手：`agents/opponents/crustle/`（stall系）、`agents/opponents/zoroark/`（counter-aggro）

## よく踏む落とし穴

- **勝者の呪い**：異常に悪い測定値をきっかけに実験を設計し、その異常値をベースラインに使うと平均回帰で「効果」が出る（D-2で踏んだ）
- **発火率未確認のまま評価**：改修前に `confirmed-facts.md` F-3のような発火率カウンタを入れること
- **ラダーとローカルの逆転**：ローカル勝率でデッキ優劣を断言しない（`confirmed-facts.md` F-5参照）
