# 役割分担とワークフロー

## 3役割の分担

| 役割 | 担当 | やること | やらないこと |
|------|------|---------|------------|
| **Cowork** | 作る | デッキ構築・エージェント実装・ファイル管理 | 採否判定・統計検定 |
| **評価ハーネス環境** | 測る | N=400〜1,000対戦・CI計算・発火率監査 | 設計・実装 |
| **Fable** | 考える・書く | 戦略立案・writeup執筆・赤チームレビュー | 実装・実測 |

**採否判定は必ずハーネス側で行う。作る側（Cowork）に判定させない。**

## 標準フロー：新バージョン開発

```
1. 設計（Fable）
   ├── 負けログ・監査結果をインプットに仮説立案
   └── 事前登録：「主比較はXvsY、N=◯、判定基準はCI下限>◯%」を文書化

2. 実装（Cowork）
   ├── agents/lucario/vN/main.py + deck.csv を作成
   ├── scripts/check_deck_legal.py で合法性確認（errorPlayer==-1）
   └── tar.gz を生成して測定側に渡す

3. 測定（ハーネス環境）
   ├── balanced N=400〜1,000 対戦
   ├── Wilson CI・2標本差CIで判定
   ├── 有意なら新規プロセスで複製
   └── 発火率カウンタを同梱（改修評価時は必須）

4. 判定・記録（ハーネス→全員）
   ├── 昇格：decision-log.md に追記 → ラダー提出
   └── 非昇格：decision-log.md に追記 → 原因分析 → 次サイクルへ
```

## 標準フロー：メタ測定（ガントレット）

```
1. 相手デッキをCoworkで作成（scripts/check_deck_legal.py 必須）
2. ハーネスで v2 vs 相手 N=400 balanced
3. マッチアップ表を experiments/results/ に保存
4. 判定結果を decision-log.md に追記
```

## Dual-purpose原則

**全ての実験はwriteupの1節として回収できること。** 回収できない実験はやらない。

- 棄却例 → プロトコルが正しく機能した証拠として記述可
- 承認例 → 本物の改善の実証として記述
- ラダー vs ローカルの乖離 → 外的妥当性の考察章として記述

## AIセッション間のハンドオフ

`skills/llm-role-handoff/SKILL.md` の規約に従う。  
- 1文書 = 1目的（設計・実装・測定・レビューを混ぜない）
- 自己完結（受け手は文脈ゼロと想定）
- 数値は実測値のみ、信頼区間つき
- 旧版文書は使用禁止マークを付けて archive/ に隔離
